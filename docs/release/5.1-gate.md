The full NSL-KDD files (`KDDTrain+` 125,973 rows with the official `KDDTest+`, 22,544 rows):
a 5-model job (random forest, logistic regression, decision tree, naive Bayes, extra trees;
22 steps) started with Enter and cancelled with Enter at step 6 ("Cross-validation, fold 1
of 3, ... Cancelling after the current model..."). The page then said "Training cancelled.
Nothing was kept from it." The web process's private memory, sampled every 0.5 s:

| When | Private memory |
|---|---|
| Before training, the dataset loaded (60 s) | 672 MB |
| Training | up to 872 MB |
| Cancelling (the model being fitted finishes) | up to 943 MB |
| After the end (25 s, 49 samples) | 708 MB, steady |

No `bundles/` or `runs/` folder appeared in the instance. The same workspace then trained
decision tree + random forest to the end (10 steps; up to 948 MB), and exported one bundle and
one run record: the only files there afterwards.

## The whole flow with the keyboard only (§8, v5.1)

Upload File (Enter) → Next → Explore: target `attack`, Analyze Class Distribution (Enter;
"Recommended Method: Class Weights") → Back and the step bar (Shift+Tab, Enter) → Features:
Recommend Features (Enter; 10 features ticked, scored on the 125,973 training rows) → Train:
models ticked and unticked with Space, Train Model (Enter), Cancel training (Enter), a second
training → Next → Use: Predict File (Enter; 22,544 rows), the download link reached, the export
name typed, Export Models (Enter). Each step's heading took focus after Next or a step button.

Focus during a training (fix `17c3e3f`), checked every 50 ms: Train → the status → Cancel
training; Cancel → the progress → the result; at the end of a training → the result. Focus was
never on the page body. Before the fix's last part, one 100 ms sample caught it on the body
while the job was being submitted; the status now takes focus first. The status and the
progress show the browser's focus ring after keyboard use.

Status messages: every message area is `role="status"` and the progress is
`aria-live="polite"` (`tests/web/test_templates.py::test_status_messages_are_announced`).

Contrast (`scripts/contrast_audit.js`): 0 failures, 0 unmeasured, on the Train step (1,748
texts) and the Use step (185 texts), in light and in dark. One reading taken right after a live
theme switch caught a colour transition half way (1.59:1 on the file field's text); after a
reload in dark the same text is `rgb(203, 213, 224)` on `rgb(45, 55, 72)`, and the full audit
passed.
