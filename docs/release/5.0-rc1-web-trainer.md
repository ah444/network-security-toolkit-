# Web trainer on the v5 core: end-user check (step 0.4g)

Recorded 2026-10-20 on Windows 10, Python 3.14.3, scikit-learn 1.8.0. The app was
started from `.claude/launch.json` (waitress on `127.0.0.1:5000`, the real `instance/`
folder) and used in the desktop app's browser pane, which was **307–322 px wide**, so the
whole session also checks phone width.

Every step was a click in the real page. The only shortcut was the operating system's
file dialog, which the browser pane can't drive: the chosen file was put into the page's
own file input from a temporary folder (deleted afterwards), and the downloaded bundle was
taken from `instance/bundles/` instead of the Downloads folder.

Data: real rows only (tier 2 samples, see the checklist rules). **The scores below are
from samples and a few features; they are not results.**

## 1. CIC-IDS2017 (`CIC-2017_sample30k.csv`)

A stratified 30,000-row sample of the original `CIC-2017.csv`, written with its raw
header (leading spaces, `Fwd Header Length.1`).

| Step | What the page showed |
|---|---|
| Upload | 30,000 rows; "Detected dataset: cic_ids2017 (original); label column: Label; split: stratified"; 78 columns (the duplicate `Fwd Header Length.1` dropped); `Label` preselected as target; 77 features and the default models ticked |
| Analyze Class Distribution | 15 classes of the whole file (labels like `Web Attack - XSS` cleaned); recommendation **from the 23,352 training rows only**: Class Weights (15 classes, extreme imbalance); the balancing select switched to it |
| Preview on training split (SMOTE) | every class grown to 18,817 rows on the training split; the dataset still had 30,000 rows afterwards |
| Recommend Features (k = 10) | scored on 23,352 training rows after the leakage guard; exactly those 10 features ticked in the list |
| Train (Recommended balancing; Random Forest, Logistic Regression, Decision Tree) | "stratified — 23,352 training rows, 5,836 test rows; 812 duplicate rows removed before splitting"; the optimistic-split warning; balancing resolved to Class Weights; leaderboard with CV mean ± std and the single test score; Random Forest selected by CV (0.579 ± 0.017); test confusion matrix |
| Predict (session, Random Forest) | a real DDoS row → **DDoS** |
| Export as `cic_sample_rf` | "Saved as a signed bundle", run id and SHA-256, a `Download cic_sample_rf.bundle` link; `instance/bundles/<run>.bundle` and `instance/runs/<run>.json` written, the record's `bundle_sha256` equal to the file's; `instance/signing.key` created (gitignored) |
| Clear workspace, then "Yes, I have a trained model" → Load Model | in the fresh workspace: "Loaded 3 model(s) from run …", trained on `CIC-2017_sample30k.csv`, each model's CV and test macro-F1 as before the export, Random Forest preselected, a prediction form for the 10 features |
| Predict (loaded) | the DDoS row → **DDoS** (Random Forest); a real BENIGN row → **BENIGN** (Random Forest and Decision Tree) |
| Load a CSV renamed to `.bundle` | "The file is not a toolkit bundle …"; nothing loaded |
| Load the bundle with one byte changed | "The bundle's signature does not match this install's signing key … Nothing was loaded." |

## 3. Phone width and errors

- After the fixes below, the page is exactly as wide as the 307 px view; wide tables
  (preview, leaderboard, confusion matrix) scroll inside their own boxes.
- No JavaScript exceptions; no server errors. The only failed requests were the three
  deliberate negative checks (`/predict` after clearing the workspace and the two refused
  files, all HTTP 400).

## Fixed during this check

| Seen | Fix |
|---|---|
| The page scrolled sideways by 11 px: split warnings were shown as long codes (`STRATIFIED_SCORES_MAY_BE_OPTIMISTIC`) that can't wrap | plain-language text for every split reason/warning code (the code stays as a tooltip); `.message` wraps long words |
| Model checkboxes were announced by their description, not their name | the description is now a tooltip on the text, so the checkbox is named "Random Forest" etc. |
| `KDDTest+.txt` was shown and recorded as `KDDTest.txt` | the upload keeps the file's own name for messages and the run record (no folder parts); only the temporary file on disk uses the sanitised name |
