## F2 The full leaderboard [F2]
Approved 2026-10-30 with: charts of the session's run in the trainer, beside the leaderboard that ships since 0.4d; a page of its own, `/runs`, that lists the saved runs and compares two of them, with no upload and no training; the CLI lists and compares them too. Decisions:
- **Only records are read.** The page reads the TrainingRun records (`instance/runs/*.json`, 30–70 KB, about 1 ms each) and never a bundle: nothing is unpickled, no model is loaded. They are read when the page or the command asks, never at start-up, during a training or during a scan
- **A list has at most 50 runs**, newest first, then "Older runs". No cache for now (F6 can add one if the history grows)
- **Which runs:** those saved with Export (a record is written then, as since 0.4e); saving every training is F6. The page says so
- **The differences (Δ) are shown only when the two runs scored the same test rows:** the same dataset (SHA-256), the same test file (or none), the same split (strategy, seed, test size, official mode) and the same training and test row counts. Otherwise the two runs are side by side, with no Δ, and the page says why
- **The records are data, not code:** a run id is checked against the form the toolkit writes (`YYYYMMDDTHHMMSSZ-` and 8 hexadecimal digits) before any path is made, a file is read only from `instance/runs/`, a record that isn't a TrainingRun, or is newer than this toolkit, is left out of the list and counted, never a 500; the page puts every value in as text
- **Access:** the same as the rest of the API (the token when opened with `--host`); the routes only read
- **The charts** are SVG made by `charts.js`: every number also written as text, a title and a text description for screen readers, colours from the theme's tokens (at least 3:1 against the card in both themes), inside a scroll box on narrow screens
- The home page keeps its four cards (a fifth would leave one alone on a row); the page is linked from the navbar and from the export's message
