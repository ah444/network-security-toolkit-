- Complexity 10 (ruff `C901`, `[tool.ruff.lint.mccabe] max-complexity = 10`) and 400 lines per Python/JavaScript file in `toolkit/` (not CSS, not `scripts/`) make a check fail so the code is reviewed; the way out is a split with a real benefit or a recorded exception with a reason (a file's exception records its line count as an exact ceiling). - Every suppression (`noqa`, `type: ignore`, `pragma: no cover`, `per-file-ignores`) in `toolkit/`, `scripts/` and `tests/` is listed in one inventory with its file, rule, count and reason; a new one, a higher count or a stale entry fails a test. - A docstring for every class, function and method in `toolkit/` (not dunder methods, not functions nested in a function); they say what the name does not: security assumptions and order, leakage and correctness, memory
- The scan contract: resolving a host name (DNS) may happen before the authorization question, so the user confirms the actual address; no packet reaches the target and nothing goes to AbuseIPDB, NVD or the AI before the validation, the limits, the authorization and the opt-in; a private address never goes to AbuseIPDB; NVD and the AI get the product and version only
- `load_dataset`'s refactor keeps its memory and time: each run in a fresh process after a discarded warm-up run; B = working set after the imports, P0 = the peak at that point, P = the peak right after the load; a run counts only if P > P0 and uses P − B; median of 3 (5 if the times vary by more than 10 %); at most +5 % on P − B and +10 % on the time, else that refactor stops and the numbers are shown
- A question that changes the architecture, behaviour, security or performance goes to the user with the options; only the work depending on it waits
