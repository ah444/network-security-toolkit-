# v5.1 Implementation Checklist — "Clean architecture"

Day-to-day driver for v5.1. The **why** behind each item is in [IMPROVEMENT_PLAN.md](IMPROVEMENT_PLAN.md) (§2 architecture, §6.2 refactor map, §7 roadmap "v5.1"; IDs in brackets). v5.0 is done: [V5.0_CHECKLIST.md](V5.0_CHECKLIST.md), tags `5.0` and `5.0.1`.
Rules:
- Same as v5.0: a test first, then the smallest change, then commit. One item = one commit. Nothing starts without the user's approval of its step.
- **Strangler moves, no behaviour change:** code moves into `toolkit/` one module at a time; every existing test passes before and after each move (tests change only their imports). New behaviour (jobs, cancel, API) comes only in the step that lists it.
- "Green" = `python -m pytest`, ruff and (from 1.1e) mypy pass on the **Windows** PC with **Python 3.14**. Linux/macOS: portability rules as in v5.0, not tested on real machines.
- Real-data checks: the three tiers of v5.0 (fixtures for every change, samples per step, full files only at the tag gate).
- `pip-audit` (environment and `requirements.lock`) runs at the end of every step and at every tag, not only at the tag (lesson from 5.0.1).
