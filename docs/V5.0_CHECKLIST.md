# v5.0 Implementation Checklist — "Correct & safe"

Day-to-day driver for v5.0. The **why** behind each item is in [IMPROVEMENT_PLAN.md](IMPROVEMENT_PLAN.md) (IDs in brackets).
Rules:
- Write the test first (it fails), then make the smallest fix, then commit. One item = one commit.
- No v5.1 restructuring during v5.0. Ugly-but-tested code inside `app.py` is fine.
- `(manual)` = checked by hand, not by the test runner.
- "Green" = `python -m pytest` passes on your **Windows** PC with your current **Python 3.14**. Everything is local: no GitHub, no WSL, no nox.
- Linux/macOS: the code follows the portability rules (plan §7, CI host) so it should run there unchanged; it just isn't tested on real Linux/Mac machines.

**Status:** **5.0-alpha tagged** (2026-10-20): 0.1, 0.1b, 0.2, 0.3, 0.7 and 0.8 done. 5.0-beta in progress: 0.4a done (loader, profiles, leakage guard; UNSW profile waits for a real file), 0.4b done (dedupe + split). Next: 0.4c pipeline.

### 0.4b Split
- [x] Dedupe before split; report dedupe stats [L4] — test: `tests/ml/test_split.py::test_no_duplicate_across_train_test`, `::test_dedupe_keeps_first_occurrence_and_reports_conflicts`. `toolkit/ids_core/split.py`, settings in `toolkit/config.py` (`SplitConfig`: test share 0.2, seed 42). First copy kept; identifier columns (profile-blocked, name-pattern hits such as `Flow ID`/`Timestamp`, time/group column) are not compared, so two flows differing only in their ID count as copies; rows with the same features but different labels are counted (`conflicting_rows`), not removed; rows without a label are dropped (`LABEL_MISSING_ROWS_DROPPED`)
- [x] Strategies: official / temporal / temporal_per_class / group / stratified (fallback with warning) [L5, D9] — tests: `::test_nslkdd_uses_official_split`, `::test_temporal_per_class_ordering`, `::test_group_never_spans_split`, `::test_cic_without_time_column_uses_stratified_with_warning`, `::test_group_fallback_skipped_when_class_one_sided`. Fallback chain: official → stratified; temporal → temporal_per_class → group → stratified; temporal_per_class → group → stratified; group → stratified. Equal timestamps never straddle a cut, so within each class every test time is **later** than every train time. User override recorded (`overridden`, `profile_strategy`). *Decision: in an official split, test rows that also occur in train are removed (`OFFICIAL_TEST_OVERLAP_REMOVED`, count in `test_overlap_removed`); scores are then not directly comparable with papers that use the full KDDTest+*
- [x] Time-column validation + fallback with **enumerated reason codes** [D9] — test: `::test_broken_time_column_falls_back_with_reason_code` (asserts `TIME_PARSE_FAILURE_RATIO_EXCEEDED`, `TIME_MISSING_RATIO_EXCEEDED`, `TIME_FORMAT_AMBIGUOUS`, `TIME_NON_MONOTONIC_ACROSS_FILES`), `::test_missing_time_column_falls_back_with_reason_code`, `::test_class_with_a_single_timestamp_is_too_coarse`, `::test_day_first_resolved_from_values`, `::test_month_first_resolved_from_file_order`. Limits: ≤ 1 % empty, ≤ 1 % unparseable (the few unusable rows are left out of a temporal split, `TIME_MISSING_ROWS_DROPPED`). `d/m/Y` vs `m/d/Y`: the reading with fewer failures wins, else the one that goes backwards less in file order; harmless when both order the rows the same way (`same-order`, true for CIC's July dates). *Not checked: clock order **inside** one file (only overlaps **between** files), because the CIC files with timestamps aren't available locally to see what their real order looks like*
- [x] Class-coverage check — test: `::test_missing_class_in_test_reports_CLASS_MISSING_FROM_TEST`. Per-class train/test counts in `SplitResult.coverage`; for temporal/group a one-sided class is a reason to fall back, otherwise a warning (`CLASS_MISSING_FROM_TEST` / `_FROM_TRAIN`)
- [x] (manual) Real-data check, 2026-10-20 (`docs/datasets.md`): `CIC-2017.csv` 308,381 copies removed (matches the 10.9 %), stratified 2,017,889 / 504,473, every class on both sides (Heartbleed 9/2, Sql Injection 17/4), 1,396 conflicting rows, 53 s; DDoS file −23,416 copies, 161,864 / 40,465; NSL-KDD official: 610 KDDTest+ rows also in KDDTrain+ removed (22,544 → 21,934), 17 test-only attack types reported as `CLASS_MISSING_FROM_TRAIN`, `spy` and `warezclient` as `CLASS_MISSING_FROM_TEST`
